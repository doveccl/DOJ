# Web AI 规则

## 范围

本文件约束 `apps/web/`。这里负责 Vue 前端、页面信息架构、视觉密度、响应式行为和浏览器侧 WebSocket 展示。

## 技术栈

- 使用 Vite + Vue 3 + TypeScript + Naive UI + SCSS。
- 使用 `unplugin-auto-import` 自动导入 Vue、Vue Router、Pinia 常用 API；不要为 `ref`、`computed`、`watch`、`onMounted`、`useRoute`、`useRouter`、`RouterLink`、`defineStore` 等重复写 value import。
- 使用 `unplugin-vue-components` 自动导入 Naive UI 组件和本地通用组件；纯模板组件不要手写 value import。`h(NTag)` 这类脚本渲染中直接引用的组件可以保留 import。
- 纯代码编辑使用 `CodeEditor`，不要用 Markdown 编辑器承载代码输入。

## UI 原则

- DOJ 是教学/训练 OJ，不是营销站点，也不是复杂后台。页面要紧凑、任务导向，避免 dashboard 式堆叠和重复标题说明。
- 默认分页为 50；表格在移动端使用组件内部横向滚动，不能撑出页面级横向滚动。
- 顶级导航固定为：首页、题库、作业、比赛、讨论、排行、提交、管理。作业仅登录显示，管理仅 admin 显示。
- 普通用户和管理员默认使用同一业务页面；管理员能力渐进显示在题库、题目详情、作业、比赛等业务页面中，不为题目/作业/比赛另建后台设置页。
- 管理菜单只放通用设置、成员、语言、评测机。
- 管理员需要能切换或识别普通视角与管理全知视角，用于检查隐藏、删除、封榜和报告裁剪。
- 前端隐藏不是安全边界；敏感字段必须由 API 裁剪，前端只渲染已获授权的数据。

## 页面职责

- 首页只展示下一步行动：推荐题目、我的作业、近期比赛、提交热力图和轻量公告。
- 题库展示 solved、题号、标题、标签、通过率；管理员可创建题目、切换可见、删除/恢复。
- 题目详情是唯一题目详情；题面与元信息分栏，底部整宽提交区；管理员在同页编辑题面、元信息、`data/`、`assets/` 和 custom 评测资源。
- 提交列表展示状态、题目、用户、语言、资源、分数和创建时间，并用 WebSocket 更新当前页运行中提交。
- 提交详情展示最终状态、源码权限裁剪提示、消息、测试点和运行中 progress；AI coaching 只由用户主动点击。
- 作业列表/详情、比赛列表/详情在同页渐进显示管理员创建、编辑、报告、删除/恢复入口。
- 比赛详情固定使用 tabs：题目、榜单、提交。管理员真实榜单文案用“查看真实榜单”，不要直接使用 `reveal`。
- 讨论区使用 topics/posts 心智：列表展示标题、作者、tags、更新时间，详情展示首楼和回复。
