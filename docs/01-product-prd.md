# 产品 PRD

## 产品定位

DOJ 是一个面向教学和训练场景的 Online Judge。它不是营销站点，也不是复杂后台系统；核心价值是让学生快速找题、提交、查看结果，让管理员快速维护题目、作业、比赛、成员和评测机。

## 角色

- 访客：可在配置允许时浏览公开题库、比赛、排行、提交和讨论；不能提交、回复、做作业。
- 登录用户：可提交题目、查看自己的作业、参与讨论、查看个人资料和提交详情。
- 管理员：由 `users.admin=true` 表示，拥有成员、题目、比赛、作业、语言、评测机和系统设置管理权限。
- Judge Agent：机器角色，只连接 server 执行统一 A/B 评测，不访问数据库、缓存或对象存储，也不感知题目原始是否有 Dockerfile；Runner 是 Agent 内部执行模块。

## 全局产品原则

- 同一页面按角色渐进披露内容，服务端负责裁剪敏感字段，前端只负责渲染。
- 不依赖前端隐藏保护敏感数据。
- 题目详情是唯一题目详情；不存在“比赛题目详情”和“作业题目详情”。提交属于哪些比赛由后端按时间窗口判断，属于哪些作业由后端按分配范围和截止时间判断。
- UI 要紧凑、任务导向，避免每页标题/副标题样板文案。
- 学生端不展示后台仪表盘式统计堆叠。
- 管理端也避免冗余页面标题，导航已经表达位置时不重复解释。

## 核心对象

- 用户：账号、邮箱、简介、管理员标记、禁用状态。
- 组：教学/成员分组，不表达全站权限。
- 题目：题面、限制、标签、可见性、软删除状态、S3 题目资产。
- 提交：用户、题目、语言、源码、上下文、最终状态、最终测试点结果。
- 作业：截止时间、分配组、额外分配用户、题目列表和报告。
- 比赛：OI/ICPC、时间窗口、封榜时间、题目列表和榜单。
- 讨论：topics/posts，两表模型；首楼是首个 post。
- 语言：提交语言及其 Dockerfile/source 文件名。
- 设置：管理端可编辑的少量运行时配置。
- 评测机：运行态 Agent 列表和接入指引，不是 PostgreSQL 业务对象。

## 首页

首页保留，但只展示用户真正需要的下一步行动。

宽屏三栏：

- 推荐题目：推荐未 AC 的公开题目。
- 我的作业：登录用户显示自己的作业，完成/未完成都显示；访客显示登录引导或空态。
- 近期比赛：只显示未结束的比赛，不显示已结束比赛。

三栏上下可放全年提交热力图，类似 GitHub contribution heatmap。热力图优先体现个人训练节奏，访客可隐藏。

访客热力图行为固定为：前端不主动请求；如果请求后收到 401，则显示登录提示。

管理员和普通用户使用同一首页视图，不额外加系统统计卡片。

## 题库

题库是公开练习入口。

展示：

- 题号、标题、标签、通过率、个人 solved 图标。
- 搜索和 tag 筛选。
- 默认分页 50。
- 管理员可从题目行进入对应题目管理。

不展示：

- 大量后台统计。
- 每题具体通过人数和提交数同时堆叠；优先展示通过率。

## 题目详情

题目详情是统一入口。

展示：

- Markdown/WYSIWYG 渲染后的题面。
- 元信息：时间限制、内存限制、标签、通过率、最近我的提交。
- 提交区域放在页面下方，代码编辑器需要足够宽。
- 如果当前用户处于相关作业/比赛窗口，可显示简洁上下文提示，但不创建独立详情页。

固定布局：

- 宽屏可左侧题面，右侧元信息。
- 提交区在下方整宽展示。

## 提交

提交列表：

- 默认分页 50。
- 支持题目、用户、语言、状态、比赛/作业等筛选。
- 显示状态、题目、用户、语言、时间、内存、分数、创建时间。
- 使用 WebSocket 更新当前页相关提交状态，不固定轮询。

提交详情：

- 显示最终状态、分数、资源、源码、消息、测试点结果。
- 运行中显示 WebSocket progress 和 per-case 摘要。
- 测试点很多时分页或折叠，超过 50 不要一次性撑开页面。
- AI coaching 是用户主动点击的可选功能，不自动生成，不落长期历史。

## 作业

作业用于教学布置。

规则：

- 作业不设置开始时间，创建后立即对分配对象生效；只设置截止时间 `endAt`，提交时间满足 `createdAt < endAt` 才计入作业。
- 删除 late/allowLate 语义。
- 删除作业级 AI 开关。
- 作业可分配给 groups，也可额外分配给 individual users。
- 截止前可编辑结构字段；截止后只允许修改标题、描述等非结构字段，并允许软删除/恢复。
- 非作业范围用户仍可提交公开题目，但不计入该作业报告。

学生端：

- 作业列表分页 50。
- 作业详情展示题目、完成状态、尝试次数、best score/AC、最后提交；attempts 固定统计提交时写入该 `assignmentId` 的所有提交，包含 CE/SE。
- 作业结束后是否还能练习由题目可见性决定，但不再计入作业统计。

管理端：

- 支持创建、未开始编辑、软删除/恢复。
- 报告为用户 x 题目的 AC、attempts、best score、last submission；attempts 不按用户去重，按提交次数统计。

## 比赛

比赛支持 OI 和 ICPC。

规则：

- 比赛题目关系只保存题号 key 和排序，不保存 per-problem score。
- 比赛时间窗口固定为 `[startAt, endAt)`，包含开始时刻，不包含结束时刻。
- OI 使用原题评测结果 `score` 统计，每题取该用户在本场比赛上下文中的最后一次提交的 score；最后一次按 `createdAt DESC, id DESC` 判定，封榜只影响普通用户展示，不影响后台真实榜单统计。
- OI 榜单按 totalScore 降序、最后有效提交时间升序、userId 升序排序；名次使用竞赛排名，并列判定只看 totalScore 和最后有效提交时间，不看 userId，例如 `1,1,3`。
- ICPC 使用通过数和罚时：solved 降序，penalty 升序，userId 升序。
- ICPC 名次使用竞赛排名，并列判定只看 solved 和 penalty，不看 userId。
- ICPC 罚时为首次 AC 距离比赛开始的分钟数向下取整，加上 AC 前每次计罚错误 20 分钟；计罚错误包含 WA、PE、TLE、MLE、OLE、RE，不包含 CE 和 SE；未 AC 题不计罚时。
- 题目满分固定为 100，首版不开放配置。
- 未开始前普通用户不看到题目列表。
- 进行中只允许修改标题、描述等非结构字段；结构字段包括 type、startAt、endAt、freezeAt、题目列表和题目顺序。
- 结束后原则上不可修改，只允许软删除/恢复等管理操作。
- 报名、私有比赛、参赛范围首版不做；这是有意简化，任何登录用户在比赛窗口内提交比赛题目都会进入该比赛榜单。

封榜说明：

- OI 比赛管理界面不展示 `freezeAt`，数据库保存 `NULL`；OI 从 `startAt` 起即封榜，选手在 `endAt` 前只能看到已提交/评测中/已评测，不看到自己的 status、score、case、message。
- OI 普通榜单在 `endAt` 前不展示真实 per-problem score、总分和排名；固定展示参赛用户与每题已提交/未提交占位。`endAt` 后普通榜单展示真实结果。
- ICPC 管理界面的 `freezeAt` 默认预填为 `endAt - 1h`，管理员可修改；后端按保存的 `freezeAt` 执行，保存为空表示不封榜。
- ICPC 封榜后选手自己的提交详情继续显示真实 verdict，但榜单对所有普通用户一视同仁，不做个性化榜单。
- 管理员默认也看到普通 frozen scoreboard；管理端可通过“查看真实榜单”查看 full scoreboard。
- UI 不应直接用 `reveal` 这个英文词。

比赛页：

- 列表分页 50，支持当前/即将/历史筛选。
- 详情固定用 tabs：题目、榜单、提交。

## 排行

全局排行按 AC 数降序、提交数升序、最近 AC 时间升序、userId 升序排序。通过率口径为 solved users / attempted users；attempted users 是至少提交过一次该题的去重用户数，包含 CE/SE；attempted users 为 0 时通过率显示 0%。

## 讨论

讨论区用 `topics` + `posts`。

规则：

- `topics` 保存标题、标签、置顶、软删除状态。
- `posts` 保存首楼和回复内容。
- 不合并两表，因为主题元数据和楼层内容生命周期不同。
- 创建 topic 时事务性创建首楼 post。
- 首楼不允许单独删除；删除首楼等价软删除整个 topic。
- 首版不做编辑、删除、嵌套回复，复杂度类似 V2EX。
- 不做站内图片上传，可引导使用站外图片。
- 不保存 `linkedProblemId`、`linkedContestId`，通过 tags 软关联，例如 `P1000`、`Contest#1`。

## 个人资料

- 未登录访问 profile 时显示登录提示或跳登录。
- 展示 Gravatar 头像，不做站内头像上传。
- 头像与邮箱关联，因此用户必须支持修改邮箱。
- 修改邮箱需要邮件验证码。
- 管理员可修改用户邮箱、用户名、简介、admin、disabled 状态和重置密码。

## 设置

管理菜单叫“管理”。其中通用设置分组：

- 基础：站点公告、开放注册、代码默认对他人可见性、游客可访问公开内容开关。
- 邮件：SMTP 配置。
- AI：OpenAI-compatible 模型配置。

默认不开放注册。开启注册前必须配置邮件，因为注册和邮箱修改依赖验证码。不要做站点标题设置。

`代码默认对他人可见性` 只作为新提交表单中源码公开勾选框的初始值；用户每次提交可修改，提交后以该 submission 的 `public` 字段为准。

## Markdown 编辑器

- 所有 Markdown 编辑场景统一使用 `md-editor-v3`。
- 要求启用 WYSIWYG 或所见即所得体验、工具条、源码模式、只读/预览、自定义图片上传和禁用上传。
- 题目编辑允许上传站内图到本题 `assets/`。
- 讨论区不支持站内图上传。
- 展示态不能显示工具条、行号或任何 editor 痕迹。
- 纯代码编辑场景才使用 Monaco/CodeMirror。
