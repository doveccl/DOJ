# 数据与存储设计

## 存储分工

- PostgreSQL：核心业务事实，支持事务和长期持久化。
- S3 兼容对象存储：题目资产，包括评测数据、题面附件、评测资源。
- Redis：session、限流、WebSocket progress、solved/ranking/count 派生状态、短期 AI/cache 状态。
- 环境变量：部署级配置，例如数据库连接、Redis、S3 凭据、Agent secret、Runner 限制。

## 固定技术栈

- 运行时和包管理器固定使用 Bun。
- Monorepo 使用 Bun workspaces，范围固定为 `apps/*` 和 `packages/*`。
- 后端 server 沿用 `apps/api` 包名，但职责是合并 server：HTTP API、评测调度、浏览器 WebSocket 和 Agent WebSocket。
- 后端 HTTP 框架固定使用 Hono。
- PostgreSQL 访问固定使用 `postgres` + Drizzle ORM。
- schema 固定维护在 `packages/db/src/schema.ts`，迁移固定使用 `drizzle-kit generate` 和 `drizzle-kit migrate`。
- 前端固定使用 `apps/web`，技术栈为 Vite + Vue 3 + TypeScript + Naive UI + SCSS，并使用 `unplugin-auto-import` 与 `unplugin-vue-components` 降低重复 import。
- Agent/Runner Docker 控制固定使用 Docker API，首选 `dockerode`。
- API 输入校验固定使用 Zod。
- Markdown 渲染固定使用 `markdown-it` 系列；Markdown 编辑器固定使用 `md-editor-v3`。

## 固定安全参数

- 密码哈希固定使用 Bun `argon2id`，`memoryCost=19456`，`timeCost=2`。
- session token 固定为 32 字节随机数的 `base64url` 字符串。
- session Redis key 固定为 `session:{token}`，TTL 固定 30 天，每次有效访问滑动续期。
- 浏览器 HTTP API 鉴权首版固定使用 `Authorization: Bearer <token>`；浏览器 WebSocket 使用同一个 token，但固定放在 `Sec-WebSocket-Protocol: doj-auth.<token>`。
- 不做 CSRF token，因为首版不使用 cookie session；所有写接口依赖 bearer token 和 same-origin 前端调用。
- 注册验证码固定为 6 位数字，有效期 10 分钟，同邮箱重发间隔 60 秒，同邮箱每小时最多 10 次。
- 注册验证码 purpose 固定为 `register`，发送到注册邮箱；修改邮箱验证码 purpose 固定为 `change-email`，发送到新邮箱。
- 验证码 Redis value 固定保存 `{ code, userId, newEmail, createdAt }`；注册场景 `userId=null`，修改邮箱场景 `userId` 为当前用户 ID。
- 用户名固定为 3-32 个字符，只允许 ASCII 字母、数字和下划线，且首字符必须是字母或数字。
- 密码长度固定为 8-128 个字符；首版不强制大小写、数字或特殊字符组合。
- 登录限流固定为同 IP 每 10 分钟 120 次、同 IP+账号每 10 分钟 40 次。
- 注册限流固定为同 IP 每小时 20 次。
- 邮箱验证码请求限流固定为同 IP 每小时 60 次。
- 提交限流固定为同用户每分钟 30 次、同 IP 每分钟 120 次。
- 源码大小上限固定 256 KiB；提交 JSON body 上限固定 512 KiB；题目单个资产上传上限固定 64 MiB。
- seed 管理员默认用户名 `admin`，默认邮箱 `admin@example.test`，默认密码 `admin12345`；部署时可用环境变量覆盖，首次登录后必须修改密码。
- seed 必须创建 `P1000 A+B Problem` 且 `visible=true`，并同时写入 P1000 的 S3 评测数据：`problems/1000/data/in1.txt` 为 `1 2\n`，`problems/1000/data/ans1.txt` 为 `3\n`，`problems/1000/data/in2.txt` 为 `-5 8\n`，`problems/1000/data/ans2.txt` 为 `3\n`。
- P1000 题面 content 固定为 `# A+B Problem\n\nRead two integers a and b, then print their sum.\n\nInput: two integers separated by whitespace.\n\nOutput: one integer.`。
- 邮件验证码正文固定为 `Your DOJ verification code is {code}. It expires in 10 minutes.`。

## PostgreSQL 原则

保留：

- 用户、组、题目、比赛、作业、提交、最终测试点、评测任务、讨论、语言、settings。

删除：

- `files`
- `problem_files`
- `judge_agents`
- `solved_problems`
- `ai_coaching_sessions`
- 所有 `legacyId`
- 所有 PostgreSQL count cache 字段
- 注册邀请码字段

改名：

- `system_settings` -> `settings`
- `judge_languages` -> `languages`
- `discussion_topics` / `discussion_replies` -> `topics` / `posts`
- `statementMarkdown` -> `content`
- `sourceCode` -> `code`
- `open` -> `public`
- `dueAt` -> `endAt`
- `sortOrder` -> `sort`
- `sourceFile` -> `source`

## PostgreSQL 类型约束

- 所有 `id` 自增主键使用 `integer generated by default as identity`，除非字段明确声明为字符串主键。
- 所有外键 ID 使用 `integer`，与被引用主键类型一致。
- `languages.id` 使用 `varchar(32)`。
- `name`、`title` 等短名称使用 `varchar(100)`；`email` 使用 `varchar(320)`；`tags` 单项最长 32。
- Markdown/content/code/dockerfile/message 使用 `text`；应用层负责大小和截断限制。
- `timeMs` 使用 `integer`；`memoryBytes` 使用 `bigint`；`score` 使用 `integer`。
- 所有时间戳使用 `timestamptz`，API 输出 ISO 8601 UTC 字符串。
- boolean 字段必须有明确默认值；`admin=false`、`mustChangePassword=false`、`visible=false`、`public=false`、`pinned=false`。

## 目标 Schema

### users

字段：

- `id`：自增主键。
- `name`：唯一用户名，可由管理员修改。
- `email`：唯一邮箱，用户可通过验证码修改。
- `passwordHash`：密码哈希。
- `introduction`：个人简介。
- `admin`：全站管理员标记。
- `mustChangePassword`：是否必须先修改密码。
- `disabledAt`：禁用时间，空表示可用。
- `createdAt`
- `updatedAt`

说明：

- 不保存 solved/submission count。
- 不通过 group 表达全站权限。
- 禁用用户不能登录；已签发 session 在下一次鉴权时立即失效，server 必须拒绝并删除该 session。
- seed admin 的 `mustChangePassword=true`；用户成功修改密码后置为 `false`。`mustChangePassword=true` 时，除 `GET /api/auth/self` 和 `PATCH /api/auth/self` 修改密码外，其他登录态接口固定返回 403。

### groups

字段：

- `id`
- `name`
- `createdAt`
- `updatedAt`

说明：

- 只表示教学/成员分组。
- 不保留 key/builtin/manager。
- 不内置 admin/user/guest。
- 删除 group 时硬删除该 group，并级联删除 `user_groups` 和 `assignment_groups`；历史 submissions 不受影响。

### user_groups

字段：

- `userId`
- `groupId`
- `createdAt`

说明：

- 多对多关系。
- 不记录 manager 或来源历史。

### settings

字段：

- `key`
- `value`：JSON。
- `updatedAt`

分区跟随 UI，保持克制：

- `general`：基础设置。
- `smtp`：SMTP。
- `ai`：AI。

固定结构：

```json
{
  "general": {
    "notice": "",
    "signup": false,
    "publicCode": false,
    "guestAccess": true
  },
  "smtp": {
    "enabled": false,
    "_host": "",
    "_port": 587,
    "_user": "",
    "_password": "",
    "from": ""
  },
  "ai": {
    "enabled": false,
    "_baseUrl": "",
    "_model": "",
    "_apiKey": ""
  }
}
```

规则：

- `_` 开头字段是私有字段，公开 API 不返回原值，只返回是否已设置。
- 不做站点标题。
- 注册默认关闭，开启注册前必须配置 smtp。
- Agent 内部 Runner 的 output limit、Agent secret、S3/Redis/PostgreSQL 连接不进入 DB settings。

### languages

字段：

- `id`：字符串主键，默认 C/C++ 为 `cpp`。
- `name`
- `source`：源文件名，`cpp` 默认为 `main.cc`，其他语言由管理员填写。
- `dockerfile`
- `sort`
- `createdAt`
- `updatedAt`

说明：

- seed 只创建 `cpp`。
- 自定义语言 `id` 固定为 1-32 个字符，只允许小写 ASCII 字母、数字和连字符，且首字符必须是小写字母；重复 ID 返回 409。
- 不保留 enabled；不用的语言删除即可，但不允许删除最后一个语言。
- 已被历史 submissions 引用的语言不允许删除，返回 409；未被引用且不是最后一个语言时允许删除。
- 不保留 command。
- `cpp` 默认 Dockerfile 固定为：

```Dockerfile
FROM gcc:14
WORKDIR /app
COPY main.cc /app/main.cc
RUN g++ -std=c++20 -O2 -pipe -static -s -o /app/main /app/main.cc
CMD ["/app/main"]
```

- 构建后清理源码/临时文件，避免泄露和磁盘膨胀。

### problems

字段：

- `id`：从 1000 开始。
- `title`
- `content`：题面 Markdown。
- `timeLimitMs`
- `memoryLimitBytes`
- `tags`：PostgreSQL `text[]` 字符串数组。
- `visible`
- `deletedAt`
- `createdAt`
- `updatedAt`

说明：

- 不做题目版本化。
- 不保存 inline test cases。
- 不保存 caseCount。
- 不保存 solved/submission count。
- `visible` 和 `deletedAt` 语义分开。
- 普通用户和访客只能查看、提交 `visible=true` 且 `deletedAt IS NULL` 的题目。
- 管理员可查看和编辑 `visible=false` 或已软删除题目；管理员也只能提交 `visible=true` 且 `deletedAt IS NULL` 的题目，隐藏题调试必须先设为可见或走未来专门的管理评测入口。
- 作业/比赛创建和编辑时只能选择 `visible=true` 且 `deletedAt IS NULL` 的题目。
- 如果题目后来变为隐藏或软删除，普通用户不能继续提交；已有 submissions、assignment report 和 contest scoreboard 仍按历史提交统计，题目在作业/比赛详情中显示为不可用。
- 样例写在题面 Markdown 中，不是评测数据。
- 评测数据必须来自 S3 `data/`。

### contests

字段：

- `id`
- `title`
- `description`
- `type`：`OI` 或 `ICPC`。
- `startAt`
- `endAt`
- `freezeAt`：可空。
- `deletedAt`
- `createdAt`
- `updatedAt`

说明：

- ICPC 的 `freezeAt` 表示封榜时间；管理端 UI 默认预填为 `endAt - 1h`，管理员可修改，后端按保存值执行。
- ICPC 若保存时 `freezeAt` 为空，则表示不封榜；UI 不应默认提交空值。
- OI 不使用 `freezeAt`，管理端不展示该字段，数据库固定保存 `NULL`；OI 从 `startAt` 起到 `endAt` 前始终按封榜裁剪展示。
- 比赛窗口固定为 `[startAt, endAt)`。
- 未开始可编辑，进行中只允许非结构字段，结束后原则上不可改。
- 结构字段固定为 `type`、`startAt`、`endAt`、`freezeAt`、题目列表和题目顺序；非结构字段固定为 `title`、`description`。
- `description` 长度固定 0-20000。
- 不做报名、私有比赛、参赛范围；这是有意简化，任何登录用户在比赛窗口内提交比赛题目都会进入该比赛榜单。

字段：

- `contestId`
- `problemId`
- `key`：比赛内题号，例如 A/B/C。
- `sort`

说明：

- 不保存 score。

- `id`
- `title`

- `endAt`

### submissions

字段：

- `id`
- `userId`
- `problemId`
- `contestId`：后端判断后填充，可空。
- `assignmentId`：后端判断后填充，可空。
- `languageId`：字符串，引用 `languages.id`。
- `code`
- `public`
- `status`
- `timeMs`
- `memoryBytes`
- `score`
- `message`
- `createdAt`
- `updatedAt`

说明：

- 源码存 PostgreSQL。源码大小上限固定 256 KiB，提交 JSON body 上限固定 512 KiB。
- `contestId` 和 `assignmentId` 可以同时存在。
- submission 级 `timeMs` 固定取所有 case 的最大 `timeMs`；`memoryBytes` 固定取所有 case 的最大 `memoryBytes`。
- 如果 B build 失败为 CE，submission 级 `timeMs=0`、`memoryBytes=0`、`score=0`，cases 为空。
- 如果基础设施错误导致整 job SE，submission 级 `timeMs=0`、`memoryBytes=0`、`score=0`，cases 为空。
- 如果单个 case 判为 SE，cases 正常保存；该 case score 为 0，submission 级资源仍按所有 case 最大值聚合。
- 不保存 live progress。
- 不保存题目版本/hash。
- 部分分提交 status 不可能是 AC；solved 只看 `status='AC'`。
- `public` 的默认值来自 `settings.general.publicCode`，但用户可在提交表单修改；最终只以 submission 自身 `public` 字段决定源码对他人可见性。

## S3 题目资产

Key 规则：

```text
problems/{problemId}/{path}
```

固定分区：

- `data/{filename}`：评测输入输出文件。
- `assets/{filename}`：题面图片和附件，不允许子文件夹。
- 根目录：`Dockerfile`、checker/interactor 源码和 Dockerfile `COPY/ADD` 需要的文件。

示例：

```text
problems/1000/data/in1.txt
problems/1000/data/ans1.txt
problems/1000/assets/figure.png
problems/1000/Dockerfile
problems/1000/checker.cc
```

路径规则：

- 使用 POSIX `/`。
- 禁止绝对路径、空路径、`.`、`..`、反斜杠、控制字符。
- `assets/` 下首版不允许再有子目录。
- 普通用户只能 GET 公开且未删除题目的 `assets/{filename}`，不能 list。
- 普通用户永远不能读取 `data/`、`Dockerfile` 或评测资源。
- 管理员可 list/read/write/delete 整个题目资产树。

题目资产 API 只暴露逻辑 assets 名称，不使用 package/media 命名。

## Redis 派生状态

事实源：

- `submissions` 是 solved/ranking/count 的事实源。
- `status='AC'` 表示 solved。
- 比赛和作业提交计入全局 solved。
- Redis 可被 clear，统计不要求强实时，优先节省算力。

固定 key：

```text
session:{token}              STRING userId with 30d sliding TTL
rate:{scope}:{key}           COUNTER with endpoint-specific TTL
emailCode:{purpose}:{email}  JSON code/userId/newEmail/createdAt with 10m TTL
solved:user:{userId}        SET problemId
solved:problem:{problemId}  SET userId
attempted:problem:{problemId} SET userId
stats:user:{userId}         HASH solved submission lastAcAt
stats:problem:{problemId}   HASH solved attempted submission
rank:global                 ZSET userId -> rankScore
repair:stats:last           HASH time status duration message
progress:submission:{id}    JSON with short TTL
```

`rank:global` 编码：

- 事实排序固定为 AC 数降序、提交数升序、最近 AC 时间升序、userId 升序。
- Redis ZSET 的 score 只保存主排序值 `rankScore = -solved`。
- 同 AC 数用户在读取排行榜时按 `stats:user:{userId}` 中的 submission、lastAcAt 和 userId 做二次稳定排序。
- 读取排行榜时固定先取目标页附近的 solved 分组：从 `rank:global` 按 score 升序扫描，累计完整 solved 分组，直到覆盖 `(page-1)*pageSize + pageSize` 名用户；每个 solved 分组内读取所有同分 userId 后按 submission、lastAcAt、userId 二次排序，再整体切片。
- 如果某个 solved 分组超过 5000 用户，server 允许在该分组内分页读取并以 PostgreSQL submissions 聚合结果做稳定排序；不能只取 Redis 任意前 N 个同分用户。
- `attempted users = 0` 时，通过率固定返回 `0`，不返回 `null` 或 `N/A`。
- `attempted:problem:{problemId}` 是通过率 attempted users 的事实派生集合，任何终态提交都必须把 userId 加入该集合，包含 CE/SE。

修复：

- 不需要 CLI。
- 提供 cron fix，分页扫描 submissions，低优先级修复 Redis。
- 管理页展示上次修复时间、状态和耗时。
- 提供 admin-only API 手动触发统计修复。
- 首版不做 rejudge；不存在重判触发链路。未来增加 rejudge 时，必须在 API 文档补接口并要求重判完成后触发局部 repair。

## 环境变量

目标环境变量保持短名，不加 `DOJ_` 前缀。

### 必须配置

- `DATABASE`：PostgreSQL 连接串。
- `S3_ENDPOINT`：S3/MinIO endpoint。
- `S3_ACCESS_KEY`：S3 access key。
- `S3_SECRET_KEY`：S3 secret key。
- `SECRET`：server 与 Agent 共享的连接 secret，也可作为应用级签名/加密 secret 的根 secret。

### 可选配置

- `REDIS`：Redis 连接串；不填时使用统一内存 cache fallback。
- `S3_REGION`：S3 region；MinIO 通常不关心，未配置时使用兼容默认值。
- `S3_BUCKET`：S3 bucket；未配置时默认 `doj`。
- `SERVER`：Agent 连接 server 的地址；默认 `http://127.0.0.1:7974`，跨机器部署时必须配置为实际 server 地址。
- `AGENT_NAME`：Agent 展示名；默认使用主机名，取不到主机名时使用 `agent`。
- `AGENT_CONCURRENCY`：Agent 并发数；默认 `1`。
- `AGENT_CACHE_GB`：Agent 侧 A 镜像缓存上限；题目评测文件包不持久缓存。`0` 表示无限制，未配置时按 `min(4GB, 0.5 * availableDiskGB)` 估算。
- Agent 内部 Runner 的 output limit、CPU/memory 默认限制使用 `03-judge-core.md` 的固定值，不进入 DB settings。

### Redis fallback

`REDIS` 可选，但 fallback 只适合单进程开发、演示或极小部署：

- fallback 使用统一的 in-memory cache interface，覆盖 session、限流、WebSocket progress、短期 AI/cache、solved/ranking/count 派生状态。
- 进程重启会丢失 session、progress 和派生统计；cron repair 可从 PostgreSQL 重建 solved/ranking/count。
- fallback 不支持多 server，也不应用于正式生产。
- 如果配置了 `REDIS`，Redis 不可用时应 fail closed 或返回明确降级，不能静默切回内存。

Agent secret 采用 `SECRET` 环境变量，不再使用本地自动生成文件作为目标模型。Docker 部署中 server 和 Agent 分属不同容器，环境变量是最清晰的共享方式。
